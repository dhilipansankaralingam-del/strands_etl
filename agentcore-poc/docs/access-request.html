What we're deploying, in four lines

An internal service that answers staff questions by researching our documentation and drafting a written brief, with an automated quality check before the answer is returned. It runs on Amazon Bedrock AgentCore Runtime — a managed AWS service that executes our Python code in an isolated micro-VM per user session — and calls Anthropic Claude via Amazon Bedrock.

No third-party SaaS. No data leaves the AWS account or the region. Users reach it through an HTTP API behind a JWT authorizer; no caller holds AWS credentials.

The three things only an admin can do

Everything else is ordinary IAM. These are account-level and one-time.
ActionWhereWhy it's needed
Enable Claude Sonnet in Bedrock model accessConsole → Bedrock → Model access, us-east-1Foundation models are opt-in per account and region. Nothing runs until this is granted — no IAM policy overrides it.
Enable CloudWatch Transaction SearchConsole → CloudWatch → Application Signals → Transaction SearchTurns agent traces into searchable span data. Without it, monitoring and quality evaluation are both blind, and the failure is silent. Needs xray:UpdateTraceSegmentDestination, xray:UpdateIndexingRule, logs:PutResourcePolicy.
Bedrock quota increase — tokens per minute, Claude SonnetService QuotasOne user request makes five model calls in quick succession. Default quotas throttle sooner than expected.
!
Transaction Search is the one that catches people out. It reports success while silently doing nothing if the CloudWatch Logs resource policy is missing — we lost a day to exactly that.

The two roles the deployment creates

The message to send

Short version, if the tables are the attachment

Subject: Access request — agent service on Bedrock AgentCore (us-east-1)

We're moving an internal AI agent service from prototype to production. It runs on Amazon Bedrock AgentCore Runtime with Claude via Bedrock — managed AWS services, no third-party SaaS, no data leaving our account or region. Users reach it through an authenticated HTTP API; no caller holds AWS credentials.

Three things need an administrator:

1. Enable Claude Sonnet in Bedrock model access (us-east-1)
2. Enable CloudWatch Transaction Search — this is what makes agent traces searchable, and monitoring and quality evaluation both depend on it
3. A quota increase for Claude Sonnet tokens/minute

Plus a deployment role for our team — the specific permissions are in the attached table. The one grant worth your attention is iam:CreateRole and iam:PassRole, which we've scoped to role names prefixed multiagent-poc-*; the deployment creates two service roles, both trusted only by the AgentCore service principal with source-account conditions.

Spend is bounded by Lambda reserved concurrency (10 parallel sessions) and API throttling. A Budgets alert on Bedrock spend would be welcome. Happy to walk through any of it.

The two questions they'll ask

Does data leave AWS? No. Bedrock runs in-account and in-region; the model is called through an AWS API, not an external endpoint. Prompts and generated text are stored in CloudWatch Logs, AgentCore Memory (30-day expiry) and an encrypted S3 bucket (90-day lifecycle) — all under our account's existing controls.

Can it run up an unbounded bill? No. Worker concurrency caps parallel agent sessions at 10, the API is throttled at 10 requests per second, and runtime billing is on active compute rather than uptime — an idle session costs almost nothing. A Budgets alert on Bedrock is a sensible addition.

If they'd prefer a dedicated AWS account for this rather than a shared one, the answer is yes — it's the cleanest blast-radius and cost boundary, and nothing in the setup assumes otherwise.
